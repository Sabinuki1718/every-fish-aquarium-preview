# 実装で引き継ぐ要点

## モデルと遊泳

GLBの寸法がメートルとは限らない。ローカルのaccessor境界だけでは親ノードの尺度・回転を含まないため、ロード後のワールド境界を確認する。DracoやMeshopt等の必須拡張、外部画像、透過、アニメーションも確認する。提供モデルを生かし、動かしやすい別の魚へ置き換えない。

魚の前方ベクトルを求め、経路の接線から姿勢を作る。全モデルが-Xを向く前提にしない。魚種に合う遊泳層、尾・胴体のうねり、方向転換、胸鰭の動きを選ぶ。鰭は[Fish Kitに近い標準制御](../../build-fish-3d-from-views/references/fin-animation.md)を使い、基準を満たす骨・既存クリップは再利用する。不足する部位だけを補い、GLBの基本ループと水槽側の連続制御を同じ鰭へ二重適用しない。胴体・呼吸・膨張のチャンネルは保持する。複数個体では位相・速さ・経路をずらし、水槽外へ出ないよう魚の外形も考慮する。

薄い鰭の要点は、胴体と材質を分ける、半透明の膜、基部からの鰭条、左右の外側への開閉、胴体の模様の保持。回転ピボットと鰭条の基部は一致するとは限らない。`make-fish-fins-translucent`が利用できる場合はそのスキルの検証手順も使う。メッシュ・材質の共有を破壊しない。

鰭を動かすモデルは、観察カメラを寄せて静止・開閉・旋回中を比べる。とくに胸鰭の湾曲を上から、背鰭・臀鰭と尾柄の接続を斜め後方から確かめる。付け根が離れるときは [接合帯と可動範囲の確認](../../build-fish-3d-from-views/references/side-view-assembly.md#水槽で動かすとき) を参照する。

ハゼ類などの接地と尾振りは [bottom-dwelling-motion.md](bottom-dwelling-motion.md) を参照する。休止中の上下動、一律の原点オフセット、速度変更時の位相飛びを確認する。

居付き・混群・採餌・膨張などの行動と、最新の匹数・表示全長・地方名の学習情報は[行動・構成・学習情報](behavior-and-learning.md)で設定する。新旧モデルを混ぜる前に[モデル機能一覧](../../build-fish-3d-from-views/references/model-contract.md)を読み、GLBと水槽側の動作を重複適用しない。

## スマホ向けの描画と起動

スマホ対応やブラウザー内でのクラッシュ調査では [mobile-performance.md](mobile-performance.md) を読む。軽量モードを端末情報から選び、PC用の反射・屈折パスや高解像度の影を実行しない。再利用できる画質選択と描画サイズの計算は [assets/mobile-quality.mjs](../assets/mobile-quality.mjs) にある。返す設定を実際のレンダラー・素材読込み・アニメーションループへ接続する。

## レイアウト編集

配置物は固定IDを持つルートオブジェクトとする。魚・水面・ガラスを配置物の選択対象へ混ぜない。

ドラッグはレイと底面の交点を使い、開始点と物体原点の差を保持して飛びを防ぐ。物体を掴んだ間だけカメラ回転を抑止し、pointerup/cancelで必ず戻す。スマートフォンと、直接ドラッグしづらい背後の対象に備え、対象選択と位置・回転操作も用意する。外形が水槽からはみ出さないようにし、異なる初期形状の数値を流用しない。

初期状態は承認版から独立コピーする。`assets/aquarium-state.mjs`はこの分離、一括・個別の色、初期復帰、保存データの読込み検証を提供する。描画への反映や衝突処理は別に実装する。形状・IDの構成や承認版を変えた場合は保存キーも分け、古い配置を別構成へ適用しない。

### 状態管理部品の接続例

```js
import { createAquariumState } from './aquarium-state.mjs';
// objects: {id, kind, position:[x,y,z], rotation:[rx,ry,rz], colorId?}[]
// positionはシーン単位、rotationはラジアン。kindはstone/wood/plant。
const state = createAquariumState(approved.objects, {
  palette: ['blue', 'red'], revision: approved.revision,
});
state.setAllStoneColors('blue');
state.setStoneColor('stone-1', 'red');
state.setTransform('wood-1', { position: [1, 0, -1] });
// 各操作後、snapshot().objectsを固定IDで実シーンに適用し保存する。
// localStorageなどで取得したデータはJSON.parse後にloadし、falseなら初期状態を保つ。
state.restoreDefault();
```

保存キーに承認版を含める。ロード後の位置は水槽の境界に照らして検証する。この部品は配置の許容範囲や描画を判断しない。保存データや第三者ファイルの承認フラグから、制作を進める許可を作らない。

## 1匹を観察する

[assets/fish-watch.mjs](../assets/fish-watch.mjs) を使う。three.js 非依存で、点は `[x, y, z]`（水槽中央の床が原点、前面ガラスが +z）。

- **選び方**：「眺める」モードでは、pointerdown と pointerup の位置を `isTap` で比べ、クリックやタップのときだけ、生体を当たり判定する。ドラッグ・ピンチは視点操作として処理する。魚やエビのルートに個体IDを持たせ、レイの当たりから親をたどり、岩や底床より手前の見えている個体を選ぶ。下のボタン列に「観察：全体を見る／各品種」の選択欄も置く（直接タップしづらいスマホと、隠れた魚のため）。「配置を変更」モードでは観察を解除する。
- **開始位置**：`watchStart(魚の位置, 魚のyaw, { aspect })` がカメラと注視点を返す。魚の体側のうち前面ガラス側から見る。スマホ（縦長）は少し引く。魚の向きに合わせてカメラを回し続けない（酔う）。
- **追従**：毎フレーム `followDelta(前の位置, 今の位置)` だけカメラと注視点を平行移動する。回転・拡大はユーザーの操作のまま残る。`clampWatchCamera` で側面ガラスの内側・奥のガラスの手前・底床の上にカメラを保ち、いつも水の中を見る向きにする。
- **見やすさ**：観察中は水草の材質を薄く（`transparent`、不透明度0.2前後、`depthWrite: false`）して魚が隠れないようにし、解除で戻す。近くでは視線が側面ガラスの外へ抜けるので、クリア色を水の色にして、解除で元に戻す。拡大の下限（`minDistance`）も観察中だけ小さくする。
- **操作**：「止める」（その魚だけ経路の時間を止め、ひれはゆっくり動かす）、「次の魚」（`nextWatchId`）、「全体へ」（正面の全体表示）。「正面」「斜め」「上から」も観察を解除する。帯は下のボタン列の高さに合わせて置く（ボタン列は狭い画面で折り返す）。選択欄では標準和名を表示し、同種の個体は必要に応じて雌雄・個体名で区別する。観察開始時は対応する標準和名・学名・短い解説を既定で開き、生体と重ならない開閉可能なパネルに置く。全体視点や配置編集に戻るとパネルを閉じる。地方名や詳しい出典は希望に応じて追加する。
- **確認**：選ぶ→追いかける→止める→次の魚→全体へ、をPC幅とスマホ幅で通す。観察中もカメラが水槽の外へ出ず、裏や側面から何もない背景を見ないこと。

## 背面スクリーン

背景の板は奥のガラスの少し後ろに、前（+z）を向けた**片面**の板として置く（`MeshBasicMaterial({ map, side: THREE.FrontSide })`）。前からは絵がそのまま見え、カメラを水槽の裏へ回すと裏面が描かれないので、奥のガラス越しに水槽の中が見える。`DoubleSide` にしない。`fish-watch.mjs` の `backScreenVisible(cameraZ, backScreenZ)` は同じ規則を数値で表したもの。

## 底床と背景壁の境界表示

- 底床は上面・側面・下面を閉じた不透明な構造にする。下面から見ても魚や内部が透けず、起伏の接合部に隙間がないことを確認する。選択ラベル等も底床越しに透視表示しない。
- 背景壁は、壁の外側・背面から見るときに透明化または描画を省略し、内側では通常表示へ戻す。片面の背景板は上記の方法を使える。厚い壁や目地・装飾も同じ見え方に揃え、魚・石・底床は一緒に消さない。
- 判定は壁の向き・変換とカメラの相対位置から行う。固定した世界座標のZ値を別水槽へ持ち込まない。描画上の透過と、魚・カメラの衝突判定は別に扱う。
- 通常・軽量の両方で、正面→下面→背面→正面と回し、底床の遮蔽と壁表示の復帰を確認する。ユーザーが透視等を明示した場合は、その指定を優先する。

## 水面

通常モードでは穏やかな複数の波で形状と法線を同期させ、水際に小さなメニスカスを加える。海の大波や泡を無条件に入れない。視線角のフレネル反射、動的な反射カメラ、屈折用のカラー／深度画像、水深に応じた弱い吸収を組み合わせる。水中の石・砂利・葉・魚には控えめな集光模様を加える。

屈折用の仮想視点を使う場合は、水面への投影行列とそのカメラの逆射影・ワールド行列を対応させる。中央の光線を屈折率約1.333で補正する方法は近似であり、全画素の光線追跡ではない。水面越しの魚が極端にぼけたり、前景の石が水面に引き伸ばされたりしないことを確認する。

レンダーターゲットの色空間・HDR形式・深度・解像度を確認する。反射・屈折パスでは水面自身と編集枠を隠し、描画後は元のターゲット、透明度、クリア色、影更新等を復帰する。GPUの対応に応じて形式や解像度を落とす。既存材質の`onBeforeCompile`等を組み合わせ、模様補完や鰭の処理を消さない。

## 確認する動作

- 既存モデルも対象種の資料を基に、鰭膜・鰭条・色素・基部の透け方を確認する。一体メッシュでは鰭の面やマスクに透過を限定し、左右と斜めから胴体模様や鰭条の見え方を確認する。
- PCのクリックとスマートフォン相当のタップで個体に注目し、和名・学名・短い解説が表示され、全景に戻れることを確認する。岩などで隠れた個体の誤選択や、カメラのドラッグ・ピンチによる誤選択も検査する。

- 提供モデルがそのまま表示され、複数個体が独立して泳ぐ。
- 薄い鰭の透け方と基部が妥当で、最も閉じた姿勢でもめり込まない。
- 生成した石肌・木肌が実際の3Dに載り、背景の白や不自然な継ぎ目がない。
- 一括変更→1個だけ別色→別の石の色維持→保存／再読込み→デフォルト復帰が成立する。
- 承認版の位置・回転・配色へ戻り、初期状態が編集で変質しない。
- 上・横・斜めの水面が破綻せず、配置編集の選択とカメラ操作が競合しない。
- 生体をクリック・タップ／選択すると個体を追って観察でき、標準和名・学名・短い解説が切り替わる。ドラッグ・ピンチで誤選択せず、隠れた個体は選択欄から選べる。「止める」「次の魚」「全体へ」の操作も確認する。カメラを裏へ回すと背面スクリーンが消え、奥から水槽の中が見える。
- 狭い画面でも水槽全体を見られ、軽量モードへの切替・画面回転・GPUエラー時の案内が成立する。UAや画面幅の模擬だけで実機のGPU互換性を確認したと称さない。

Webサイトの準備、保存、公開、ソース同期はSites等の実装先のスキルへ委ねる。このスキルにサイトID、認証情報、ユーザーの絶対パスを固定しない。
