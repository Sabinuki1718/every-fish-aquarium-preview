# 底生魚の尾振りと接地

ビワヨシノボリ水槽の修正から得た実装上の注意。数値は受け入れられた一例で、魚種の行動研究から得た標準値ではない。別モデルの全長・座標系・生態・ユーザーの希望に合わせて選ぶ。

## 尾振りの位相を連続にする

`sin(time * speed)`のspeedを遊泳状態に合わせて変えると、過去の時間全体に新しい速さが掛かり、位相が飛ぶ。短い切替や補間中にも細かい震えに見える原因になる。個体ごとの位相を積分し、速さと振幅を別々に滑らかに変える。

```js
fish.phase = (fish.phase + angularSpeed * dt) % (Math.PI * 2);
// 尾ほど大きく動く重みを使い、原点や軸はモデルから求める。
const offset = amplitude * tailWeight * Math.sin(fish.phase - bodyPosition * waveNumber);
```

周波数をHzで持つ場合はangularSpeedへ変換するときだけ2πを掛ける。今回の遊泳中は3.6 rad/s、約1.75秒で一往復。休止中は振幅をほぼゼロにし、常時小刻みに振り続ける表現から修正した。休止・発進・方向転換・停止の動画または複数フレームで、位相の飛び、尾先の跳ね、身体の横滑りを確認する。

個体ごとの材質uniformやアニメーション状態を分け、同時刻でも全個体が同じ位相・同じ経路にならないようにする。既存のボーンやクリップが適切なら、それを調整する。

## 着底高さは実形状から求める

底面の高さに一律の数mmを加えると、全長4cm程度の魚では隙間が大きく見える。雄雌で魚体下面の位置も異なり得る。モデル原点、全身の最低点、腹側の接触位置は同じではない。

- 砂の上面と、実際に描画する石の三角形または適切な衝突形状へ、下向きレイ等で高さを問い合わせる。楕円包絡は衝突回避には有用だが、実物より高い包絡をそのまま着底面にしない。
- 魚体・腹鰭・胸鰭などの支持点をモデルから採り、親変換、拡大縮小、現在の向き・傾き・鰭変形を同じ座標系へ変換する。隣の石の最高点を魚全体の接地高さにしない。
- 各支持点の水平位置を`worldXZ`、魚ルートからの垂直変位を`dy`とすると、貫通を避けるルート高さの候補は`max(surfaceHeight(worldXZ) - dy)`。小さな許容値を加える場合は、モデル寸法に対する比と表示結果で決める。
- 全身の最低点だけでは尾鰭端や臀鰭端が先に接し、腹側が浮くことがある。腹や腹鰭が自然に支える姿勢へ調整し、尾や他の鰭も貫通しないことを確認する。今回の小さな前傾0.065 radや表面余白0.10 mmは専用の例で、別モデルへ固定しない。
- シェーダー変形や動く鰭がCPUレイキャストへ反映されない場合、その差を明示して包絡・変形の評価・姿勢確認で補う。未変形頂点だけの数値検査を完全な接触検証と呼ばない。

休止時は浮遊用の上下の正弦波を止める。遊泳時の持ち上がりと、停止後の緩やかな降下を分け、石の通過時には貫通を避ける高さを優先する。編集で石を移動・回転した場合は、衝突用の行列やキャッシュを更新する。レイキャスト対象を水平範囲で絞り、過密な支持点や毎フレームの全頂点検査による負荷を避ける。

## 接地の確認

平らな砂・石上・石の縁で、雄雌それぞれが止まる状態を横の低い視点から確認する。腹側の隙間、鰭・尾の貫通、石への乗り上がり、停止後も残る上下動、着底を示す影を一緒に見る。接触値がゼロでも、支持点が尾先だけ、地形が概算、姿勢や変形が不一致なら接地の証拠にはならない。数値検証の対象・近似範囲と目視確認を分けて記録する。
