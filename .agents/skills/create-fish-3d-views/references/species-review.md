# 魚種の共同調査・画像と3Dモデルの検品

**ユーザーが明示的に依頼した部分修正は、修正とその確認・再修正を主担当だけで行う。確認のためにサブエージェントを作成・再開・呼び出さない。ユーザーがサブエージェントも合わせた確認を明示的に希望した場合だけ、指定された範囲で共同検品する。** 以下の「共同検品」「全員OKまで反復」は共同検品の場合の規則であり、通常の部分修正には適用しない。初回の魚種調査・画像作成・3Dモデル検品は従来どおり共同検品する。

魚種名から画像を作るとき、または魚の3Dモデルを検品するときは、主担当に加え、通常は**学術・公的資料担当とホビー資料担当の2体**を起用する。観賞用改良品種が指定された場合は**ホビー資料担当1体**を起用し、品評基準・愛好家団体・実個体資料から品種定義と外観を検品する。写真がある場合も省略しない。全体スキルからの実行、画像・モデルだけの依頼、標準・ブラウザ簡易版・外部生成のどのルートにも適用する。

## 部分修正の運用
- 「ひげを短く」「斑を薄く」「この接続を直す」など、既存成果物の特定箇所を直す依頼が対象。主担当は対象と維持する部分を特定し、修正後に該当部位と影響範囲を確認する。NGが残れば主担当で再修正する。
- この会話で以前サブエージェントを使用していても、部分修正時に自動で再参加させない。一般的な「続けて」はサブ確認を希望する指示とはみなさない。
- ユーザーが「学術担当にも確認して」など明示した場合は、その希望する担当・範囲で検品する。部分修正だけを理由に全工程の再調査へ広げない。
- 全体を新しく生成する場合や次工程で新たな3Dモデルを検品する場合は、既定の共同検品へ戻る。既存のユーザー承認の境界は維持する。
- 記録に `mode: main_only` または `joint`、選択理由、今回実際に確認した担当・対象版・結果を残す。主担当だけで確認した新版へサブの旧版OKを流用しない。未依頼のサブ判定は書かない。`main_only` では主担当のOKをもって検品合格/ユーザー承認待ちとする。

## 担当の役割と引き継ぎ

- **学術・公的資料担当（academic）**は原記載・再記載・論文、博物館・大学・行政などの資料を中心に調べる。画像と3Dモデルの各検品で、対象種の同定形質をすべて照合する。各鰭の枚数・棘条数・軟条数、口ひげの本数など、資料で確認できる計数形質はすべて数え、対象の雌雄・成長段階・地域に適用される記載値または範囲と照合する。資料や成果物から数えられない項目は未確認として記録する。生時の色彩はホビー資料担当の見解を優先する。
- **ホビー資料担当（hobby）**は愛好家の飼育記録、ショップ・ブリーダーの資料、実個体の写真・動画などから、愛好家の間で一般的とされる外観を調べる。画像と3Dモデルの各検品で、全体の外観、体形、各鰭の形状、口の向き（上向き・まっすぐ・下向きなど）、生時の色彩、斑紋をすべて確認する。改良品種が指定された場合は、その品種の定義と成果物が定義に合うかも確認する。流通名や投稿の同定は学術資料と照合し、計数形質は学術・公的資料担当の見解を優先する。
  - 検品では種・性・成長段階の一致と、実個体の外観再現を分ける。色域の面積・境界・濃さ、鰭の透け、姿勢、個体差を確認し、判読できない重要形質は未確認と記録する。

主担当は検品担当へ魚種名・個体設定・ユーザーの写真・依頼内容を共有する。各担当は参考URL、対応する特徴、未確定点を独立に返す。AI生成画像を形態の根拠にしない。資料が食い違ったら出典の同定、雌雄、成長段階、品種、損傷や撮影条件を突き合わせてから採用する特徴を決める。

調査に参加した担当を画像と3Dモデルの完成後の検品にも参加させる。画像からモデルへ進む場合は同じ担当を継続して使う。会話の再開などで継続できないときは必要な役割を割り当て直し、調査と過去の判定を渡す。3D検品から始めた場合も、生成・修正前に主担当と対象の担当で必要な調査を行う。

## 写真の投影と見えない部位の補完

ユーザー写真を真横の直交投影と決めつけない。斜め・俯瞰・あおり、遠近、体の曲がりやひねり、器官の重なり・収納・欠損・画角外を確認する。見かけ上短い部位をそのまま短くしたり、写っていない部位を「存在しない」と扱ったりしない。

**補完対象は鰭に限らず、写真で見えないすべての部位。** 眼・口・鰓・頭部・胴体の厚み・背腹面・尾柄・鰭・口ひげ・棘・吸盤・その他の付属器官、体表の色や模様を含む。その種と対象の雌雄・成長段階・品種の調査結果、および別角度の資料から、自然な立体形態と直交投影を推論して補う。斜め写真の単純な引き伸ばしや鏡像コピーだけで復元しない。左右非対称な魚や模様の非対称性も調べる。

- 既定はその種の正常で完全な生体。実個体の損傷を種の標準形態として再現せず、隠れ・欠損した部位は資料に沿って補完する。特定個体の欠損も再現するというユーザー指定があればそれを優先する。
- 写真で確かめた個体の特徴を保ち、見えない部分を同種の資料から補う。別種の器官や、対象と異なる性・品種の特徴を混ぜない。
- `research.md` に「写真で確認」「資料で確認」「推論で補完」を分け、補完部位・採用形状/色・根拠URL・確度/未確定点を記す。推論を写真で観察できた事実や実測復元と称さない。両担当も補完の妥当性を確認する。
- 資料に基づく通常の補完は主担当の判断で進める。流通名に複数種が該当する場合は、候補の学名を示し、学名で対象種を指定するか、その流通名で一般的に見られる外観を代表する平均像で作るかをユーザーに選んでもらう。平均像を選んだ場合は採用した特徴と根拠を記録し、実在する単一種として同定しない。その他、種や品種の違いが結果を左右する場合もユーザーに確認する。

生成した「付属物を除いた参照画像」の下地も、この調査と補完に基づく。生成画像自体を、隠れた部位の実証資料にはしない。

## 全員OKまでの検品と修正

1. 画像生成後は、三面図・方向別PNG・必要な正面図や補助参照を主担当と対象の担当が実際に見る。3Dモデル生成後は、**そのモデルのメッシュ・UVから描画した**左右・正面・背面・上面・下面と重要部位の拡大、必要に応じて回転プレビューを全員へ渡す。別の生成画像をモデルの検品に使わない。
2. 全員が自分の調査結果と入力資料を照合し、種の識別点、部位の有無/数/位置/形、比率、色と模様、投影間の対応、補完部位を確認する。主担当は画風・画像の切れや混入物、モデルの接合・UV・透過・構造検証も担当する。
   画風が無指定の画像では、近縁種との識別形質を特に明確に、その他の同定形質も明確に残し、それ以外の細部を省略する。`research.md` で選定した比較対象と差を照合し、必要な形・数・位置・比率・斑紋境界が簡略化で失われていたらNGとする。微小でも識別に必要な部分は省略せず、誇張で補わない。識別に不要な微細な質感や装飾的描写を増やすことは求めない。
3. 全員が対象ファイルと版を明記して **OK / NG** を返す。NGは「対象部位・問題・根拠・具体的な修正」をリストにする。資料不足や対象を見られない状態は未判定とし、OKとみなさない。
4. **主担当を含む誰か1人でもNGなら**、主担当が修正事項をまとめて対象の画像またはモデルを修正する。意見の食い違いは根拠を再確認し、未解決のNGを多数決や主担当の裁量で取り消さない。
5. 新版を保存し、修正点と維持する点を添えて同じ担当へ再提示する。全員が指摘の解消と変更による不整合を確認する。局所修正なら該当部位の拡大と変更範囲で確認できるが、新版全体との対応が分かる資料を渡す。旧版のOKを新版へ自動転用しない。
6. **同じ最新版について主担当と今回の検品担当の全員が明示的にOKを出すまで、修正と再検品を繰り返す。** 全員OKになってから完成扱い/ユーザー承認待ちにする。水槽の工程では、その後さらに既存のユーザー承認を待つ。エージェントのOKをユーザーのOKに置き換えない。

ツール制限・資料へのアクセス不能・外部生成のユーザー作業待ちなどで修正や検品を続けられない場合は、未解決事項と再開条件を記録して保留する。必要な担当を起用できない環境も同様に制約を伝え、主担当だけで全員OKを装わない。制限を理由にNGをOKへ変更したり、未合格の対象を完成扱いにしたりしない。有料APIの利用や新しい外部サービスの権限は、既存の同意範囲を守る。

## 記録

魚種ごとの `research.md` に参加した担当の役割・参照資料・補完判断を残し、`reviews.md` に各回の工程（views/model）・版・対象ファイル・担当の識別子と役割・判定・根拠・修正事項・修正結果を追記する。版ごとの対象ファイルは上書きしない。単独依頼でも成果物と同じ作業フォルダにこの2ファイルを置く。

水槽プロジェクトでは `project.json` の各工程から `reviews.md` を参照し、エージェント検品とユーザー承認を別に記録する（[進行の記録](../../fish-to-3d-aquarium/references/workflow-state.md)）。後から画像・モデルを変更したらその工程の検品をやり直す。三面図を直した場合は、それに依存するモデルも再生成/修正して再検品する。
