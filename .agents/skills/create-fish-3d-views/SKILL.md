# 魚の3D生成用三面図

**ユーザーが明示的に依頼した部分修正は、修正とその確認・再修正を主担当だけで行う。確認のためにサブエージェントを作成・再開・呼び出さない。ユーザーがサブエージェントも合わせた確認を明示的に希望した場合だけ、指定された範囲で共同検品する。** 以下の「共同検品」「全員OKまで反復」は共同検品の場合の規則であり、通常の部分修正には適用しない。初回の魚種調査・画像作成・3Dモデル検品は、開始時にユーザーが選んだ検品体制（共同検品／主担当のみ。希望がなければ主担当のみ）で行う。

魚種名だけでも、**調査 → 識別特徴の選定 → 画像生成 → 三方向の整合確認 → 個別PNGの納品**まで実行する。ユーザーの指定があれば以下の既定値より優先する。3D生成サービスへのログイン・アップロード・3Dモデル生成はこのスキルの範囲に含めない。

特定の3D生成サービスに依存しない参照画像を作る。利用先が指定されている場合は、その入力仕様に合わせて画像サイズ・方向・ファイル構成を調整する。

## 既定の成果物と画風

ランチュウ型金魚は側面図を起点とする依頼でも、同じ個体の側面図と上面図を別PNGで用意し、共同検品後に同じ提出で提示する。ユーザーが出力方向を明示的に限定した場合はその指定を優先する。

- まず1種につき側面図を提示し、ユーザーの承認を得る。その後は[モデル用図面の選び方](references/model-view-selection.md)に従い、必要な背面（真上）・腹面（真下）等を追加する。三面図を作る場合は各方向を**独立したPNG**で納品する。1画像には1個体・1方向だけを含める。三面図を1枚にした原本も、作成した場合は同梱する。
- 白背景、画像内の文字・寸法線・透かし・背景小物・投影影なし。ラベルは画像外の一覧やファイル名に付ける。
- 既定は[ネオンテトラのアニメ調見本](assets/neon-tetra-anime.webp)と同じ簡潔さの**アニメ調・セル塗り**。対象魚の写真は形態・体色・斑紋の資料とする。リアル調の場合は[ネオンテトラのリアル調見本](assets/neon-tetra-realistic.webp)を参照し、ユーザー指定の画風資料があればそちらを優先する。選んだ画風は側面図、追加図、3Dテクスチャとプレビューでそろえる。
- 画風が無指定の場合の描画優先順位は、**近縁種との識別形質 → その種の同定形質 → その他の細部の簡略化**。同定・識別に必要な形、数、位置、比率、斑紋や色の境界は明確に残す。細かな鱗の質感、分節・分枝、装飾的な陰影など、識別に不要な描写は省略する。小さい部位でも識別に必要なら省略せず、形や数を変えて誇張しない。
- このスキルから新規制作を始める場合も、最初にアニメ調（既定）／リアル調／その他（自由入力）の希望を一度だけ聞き、その案内に[ネオンテトラの画風見本2枚](../fish-to-3d-aquarium/SKILL.md#画風の見本)をラベル付きで表示する。依頼や上流工程ですでに決まっている画風はそのまま使い、指定なし・希望なし・選択のスキップはアニメ調で進める。
- 「その他」は自由記述に従い、画風見本としてイラストが添付されていれば [keep-illustration-style](../keep-illustration-style/SKILL.md) の手順でその画風にそろえる。
- 8Kは画質指示と実ピクセル数を区別する。実寸を確認して記録し、1024pxなどの生成原本を8K解像度と称さない。単純な拡大で達成した扱いにしない。
- 同じ成魚の設定、同じ模様・ひれの状態・体長スケールで三方向をそろえる。基本は頭が左、尾が右、落ち着いた自然な姿勢。体型のために別姿勢が必要なら明示し、投影間で統一する。
- アルビノ・改良品種・雌雄・成長段階の指定がなければ、一般的な正常体色の成魚。食用魚も**生きた魚の外観**を対象にする。

## 1. 魚名を解決し、描く前に調査する

先に [共同調査・検品](references/species-review.md) を読み、選ばれた検品体制を確かめる（未選択なら、このスキルから新規制作を始める場合に限り、画風と同じ案内で尋ねる。希望がなければ主担当のみ）。共同検品なら対象に応じて検品担当を起用し（観賞用改良品種はホビー資料担当1体）、各担当は調査から画像・3Dモデルの検品まで継続して参加する。主担当のみなら主担当が両方の観点で調べる。主担当が調査結果を照合し、魚種ごとに次を済ませる。リストに複数種あれば全種を最後まで扱う。

ユーザー写真は真横とは限らない。投影・遠近・隠れ・欠損を見極め、写真で見えないすべての部位（鰭、眼、口、鰓、体の厚み、背腹面、付属器官、模様など）を、調査したその種の特徴から推論で補う。観察・資料・推論を分け、補完部位と根拠を記録する。詳しい補完基準は上記の規約に従う。

1. 和名・英名・流通名から学名を検索する。新しい属名と旧名・流通名を必要に応じて併記する。流通名が別種を指す例を無視しない。
2. 外観を調べる。実個体の写真、原記載・再記載、博物館・大学・行政、専門家の図鑑や識別記事を優先し、AI生成画像を形態の証拠にしない。背・腹・対ひれなど側面写真に隠れた部位も確認する。
3. 近似種と比べ、残すべき体型・吻・口・ひれの位置/有無・帯/斑/色面を選ぶ。微細な鱗、甲板、鰭条、歯や棘は識別や立体化に必要な分だけにする。
4. 「採用する特徴」「混同しない点」「省略する細部」「参考URL」「未確定点」を短く記録する。「採用する特徴」では同定形質と近縁種との識別形質を分け、後者は比較対象と具体的な差を示す。識別に必要な条数・斑紋位置・鰭の形や接続を、単なる細部として省略しない。識別に十分な情報がそろったら描画し、不要な分類史調査を続けない。

解決できない名前が実際に異なる形態を指す、など結果を左右する曖昧さだけ質問する。既知の流通名として妥当に解決できる場合は、その扱いを伝えて進める。科学的な確定同定ができないものを、絵だけで確定できると称さない。

体型が特殊、深海魚、強い雌雄差、資料が乏しい場合は [references/research-and-projection.md](references/research-and-projection.md) を読む。一般的な魚にも使える確認事項を含む。

ハゼ類・ヨシノボリ類、雌雄の描き分け、尾柄斑や眼前模様の修正では [references/goby-reference.md](references/goby-reference.md) を読む。ユーザー資料に基づく種・性・個体の特徴を分け、注記の赤線を体色として取り込まない。

## 2. 三方向を設計する

- 側面・上面・下面は同じ個体の**直交投影**として作る。別の側面や斜め上写真で代用しない。模様を背・腹へそのまま貼り付けない。
- 普通の側扁魚では上面/下面の体は細くなり、縦に立つ尾びれ・背びれ・臀びれは端から見た薄い形になる。**このルールを全魚種に固定しない**。扁平魚、エイ、特殊な尾やひれでは実際の立体形態・ひれの面を先に判断する。
- 同じ位置に接する部位の色や斑紋を三方向で対応させる。裏から隠れるひれを透視して描かない。上面/下面で対ひれを不自然に増やさない。
- 種に存在しないひれ・口ひげ・吸盤などを付け足さない。スタイル参照の魚の体型や模様を全種に使い回さない。
- 大きな付属物が胴体や頭を広く隠す魚（水泡眼の水泡、体側を覆う大きな胸鰭など）は、三面図とは別に、**その部位だけを除いた参照画像**（同じ個体・同じ投影）も作る。隠れた頭部・体表・眼の位置を調査に基づいて補完し、画像と3D化で共有するための資料とする。補助画像自体を実証資料にはしない。プロンプトは [prompt-template.md](references/prompt-template.md) の「隠れた部位の参照画像」。
- 顔の正面の印象が大事な魚（口・眼・頭の付属物が前から目立つもの）は、**正面図**も1枚作る。三面図だけでは正面向きの面に絵が無く、3D化で横からの絵が引き伸ばされて継ぎ目や二重の口が出る。
- 斑点は大小・間隔・形・密度に自然なばらつきを持たせ、均等な水玉・格子・同じスタンプの反復にしない。網目は輪の広さ・輪郭・接続・途切れを不均一にし、規則的な六角形タイルにしない。**その種に本来ある点列・帯・左右の構造まで無作為化しない**。

## 3. 画像を生成する

画像生成・内容修正は利用可能な**内蔵image_gen**を使う。imagegenスキルが利用できる場合はその手順にも従う。生成不能なら制約を伝え、SVG・プログラム描画・無断の有料APIで代用しない。

既定の側面図は**初回の画像生成から**[ネオンテトラのアニメ調見本](assets/neon-tetra-anime.webp)を画風参照として実際に添付する。対象魚の写真も添付するときは、画像ごとの役割をプロンプトで示す。見本から採るのは輪郭線、色面、陰影の省き方で、魚種の形や斑紋は対象魚の資料に従う。ユーザー指定の画風がある場合はその指定を優先する。

プロンプトは [references/prompt-template.md](references/prompt-template.md) を使い、種ごとの調査結果で具体化する。別種ごとに1回ずつ呼び出し、一枚に複数種を詰め込まない。

三方向が無理なく収まる場合は、1種1枚の三面図を生成し、上から側面→上面→下面、十分な白い隙間を確保してから分割する。長大なひれ、細長い体、扁平な体などで収まらない場合は、方向別に生成して照合する。生成サイズや投影を一律に1024×1536・三等分へ固定しない。

## 4. 目視で確認し、必要な点を直す

選ばれた検品体制（共同検品なら主担当と調査に参加した担当、主担当のみなら主担当）が、[共同調査・検品](references/species-review.md) に従って生成画像を実際に確認し、版ごとにOK/NGと修正事項を記録する。最低限、次を確認する。

- 既定の側面図は承認依頼前にネオンテトラのアニメ調見本と並べ、輪郭線、色面のまとまり、陰影、眼と鰭の描き込み量を比べる。皮膚や虹彩の粒状感、細かな鱗の反復、光沢、多段のグラデーションで写実寄りに見える場合は、識別に必要な形と模様を保って画風を直し、再比較してから提示する。

- 選定した同定形質が明確で、特に近縁種との識別形質が判読できるか。簡略化で必要な形・数・位置・境界を失っていないか、明確に見せるために誇張していないか。
- 別種の特徴、眼帯と斑点の取り違え、帯の範囲・終点、背びれの黒斑の有無など、識別点に誤りがないか。
- 三方向が成立し、体長・太さ・口/眼/ひれの位置・模様が対応しているか。余分なひれ、裏面の重複、尾の面の誤りがないか。
- 規則的すぎるスポット/網目、鱗や甲板の過剰な細密化、背景・文字の混入がないか。ひれや口ひげが画像端で切れていないか。

誰か1人でもNGなら、修正事項をリストにし、内蔵image_genへ**対象の誤りと維持する要素を限定した修正**を指示する。新版を同じ担当へ渡し、主担当を含む全員（主担当のみなら主担当）が同じ最新版にOKを出すまで修正と再検品を繰り返す。同じ誤りが残る場合は別生成や方向別生成へ切り替える。続行できない制約があれば未合格として保留し、NGを残したまま完成としない。

## 5. 保存・方向別出力・納品

生成原本を実行環境のツールが返した保存先から、ユーザー指定先または作業フォルダの`outputs/`へコピーする。仮の生成先にしか存在しない状態で終えない。

独立PNGへの分割は、ユーザーが求める方向別書き出しのための**等倍の切り出し**として行う。Pillowで模様や体型を描き直さない。目視で白い隙間を確認し、画像ごとの座標を指定する。自動三等分でひれを切らない。分割後にも各画像に1方向だけが全体で入ることを確認する。切り出し後の納品画像も検品担当へ共有し、欠けや取り違えがあれば修正して全員で再確認する。

再利用可能な梱包ヘルパー：

```text
python scripts/package_views.py <export-manifest.json> --out-dir <outputs/fish-views>
```

入力形式と使い分けは [references/export-manifest.md](references/export-manifest.md) を読む。方向別原本、三面図からの明示座標での切り出し、両方に対応する。Pillowが必要。スクリプトの出力チェックは、形態や投影の目視確認の代わりにはならない。

既定で個別PNG、存在する場合の三面図、画像一覧HTML、学名・特徴・出典・実寸・生成/修正プロンプトの記録、ZIPをまとめる。保存済みの既存ファイルを無断で上書きせず、修正依頼なら原本の控えを残すか版を分ける。

最後に個別PNGの枚数、画像一覧とZIPのリンク、実寸に関する重要な制約、解決できなかった点だけを簡潔に伝える。生成方法とプロンプト記録、調査・補完の記録（research.md）と全員の検品記録（reviews.md）も納品する。
