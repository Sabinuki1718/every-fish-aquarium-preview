# モデル機能一覧と鰭仕様

新規モデルの制作と、新旧モデルを同じ水槽へ統合する際に使う。見た目のプレビューが動くことと、GLBに再利用可能な動作があることを分ける。

## 記録する仕様

承認対象の版ごとに、JSON等で次を保存する。これは引継ぎのための記録仕様であり、自動読込み機能を提供するものではない。

- モデルID・版、和名・学名・性／成長段階、参照画像のファイル・版・ハッシュ。
- GLB・プレビューのファイルと、検品記録の参照。
- 前方・上方向・単位、親ノード変換、全長の定義と正規化方法。胴体長と全長を混同しない。
- 鰭・口・鰓・遊泳・視線・特殊動作ごとの実装状態、実装先（GLB／プレビュー／水槽）、ボーン・モーフ・クリップ名。
- 各機能の「実装済み」「未実装」「その種には該当しない」。推測で実装済みにせず、GLBを読み戻して確認する。
- 通常／軽量のモデルと画像、構造・可動・外観を確認した範囲。

既存Fish Kit由来のHTMLに動作があっても、GLBが静止ならその差を記録する。アクアリウム用の標準は鰭・口・鰓の可動。[呼吸動作](breathing-animation.md)を参照し、標準仕様を満たさない状態を完成した可動版としない。

## 既存モデルを水槽に持ち込むとき

添付の既存プレビュー、独立ローダーでのGLB単体、水槽の実行時処理について、遊泳・鰭・視線の実装先を記録する。元プレビューが動く場合もGLBのクリップ、モーフ、ボーンと水槽側で必要な補完を確認する。持ち込んだGLBを水槽で再生し、動作の欠落や二重適用を検査する。

## 標準の鰭制御

[標準の鰭アニメーション](fin-animation.md)を、側面図・三面図と画風にかかわらず適用する。部位別の基部・自由縁・可動限界、制御方式と版、基本クリップ名、GLBと水槽それぞれの実装先、速度・旋回への対応、個体別状態、置換するチャンネル、魚種別例外、検証した状態を機能一覧に記録する。GLB単体のループと水槽内の連続制御の機能差を明示する。

## 視線の仕様

ユーザーがリアル調を明示した可動モデルに限り、[Fish Kit](https://cda-social.github.io/fish/kit/README.md) の `fish-kit.js` にある眼の動きを取り入れる。視線は頭部座標で動かし、魚種の眼の構造に合わせて可動域を調整する。観察者・カメラ追従は無効にする。画風無指定のセル塗りやその他の画風では、この視線移動を追加せず、眼を頭部の姿勢や体表の変形に追従させる。魚種固有の眼の動作は個別仕様に従う。

Fish KitのGLBは単体で動かず、動作は `fish-kit.js` の実行時処理で付く。対象モデルへ移す際は、GLBで再生できる眼の動きを保存し、実行時制御を併用する場合は実装先と差を記録する。正面・側面・真上・斜めから、視線の可動域の端と頭部の動作との同時再生を確認する。GLB、プレビュー、水槽で、眼の埋没・突出・カメラ追従がなく、リアル調を指定していないモデルでは視線が動かないことを確認する。

## 鰭の仕様

魚種と各部位について、次を承認図・調査資料から記録する。

| 項目 | 記録する内容 |
|---|---|
| 構造 | 存在の有無、左右一対／癒合／正中、独立した棘・条 |
| 配置 | 基部の線・曲線、接合帯、左右の間隔と向き、参照した方向 |
| 材質 | 不透明／半透明の判断と根拠、膜・鰭条・模様の分け方 |
| 可動 | 支点、閉じる限界、開く範囲、基部からの滑らかな曲がり |
| 姿勢 | 着底時の支持点、他部位に隠れる範囲、遊泳時との違い |

側面で見えない対鰭を欠損とせず、重なりと実際の構造を別方向の資料で確認する。今回のミズタマハゼでは着底時のうちわ状胸鰭と、その後ろに隠れる腹鰭を扱った。すべてのハゼを同じ構造・配置にしない。

透明度を全鰭へ一律適用しない。今回のスジアラ・カンモンハタの胸鰭は不透明寄りにしたが、分類群全体の固定値にせず種・部位の資料で判断する。半透明膜の場合は胴体色を直接焼き込まず、[鰭の半透明化](../../make-fish-fins-translucent/SKILL.md)を使う。

基部が浮く場合と自由縁が胴体へ埋まる場合を分け、鰭全体を内外へずらすだけで直さない。最も閉じた姿勢から全開まで確認する。

## 可動と複数個体の検品

静止・最小・最大・中間、実際に同時再生する動作の組合せとループ端を確認する。通常版・軽量版の機能差も記録する。[外観と構造の検査](quality.md)に従い、閉鎖検査の合格を鰭の面積・模様・可動の合格と混同しない。

群れでは形状・画像等を共有できるが、個体ごとの再生位相・モーフ重み・行動状態を独立させる。一匹の操作で全個体の表情・動作や材質が変わらないことを確認する。インスタンシング等を使う場合も、必要な個体別変形に対応する実装を選ぶ。
