# 口・鰓の呼吸動作

アクアリウム用では、側面図・三面図のどちらから作っても、魚種に合う鰭の動きに加え、小さな口の開閉と鰓の呼吸動作を標準納品に含める。ユーザーが静止モデルを明示した場合は従う。制約で実装できない機能は未実装と記録する。

## 境界を図とモデルで一致させる

1. 承認図の口先・口角・顎関節、鰓蓋後縁・付け根を魚種ごとに記録する。鰓蓋の輪郭は下側への回り込みまで読み、図へ重ねた確認画像を残す。単純な縦線や汎用の座標に置き換えない。
2. UV投影で描画位置が変わる場合は、その投影を通して実モデル上の線を求め、切れ目を一致させる。非対称な魚や反対面はその面の資料を使う。フグ類の小さな鰓孔など、異なる構造へ一般魚の鰓蓋を移植しない。
3. 口は資料に合う顎関節から小さく開く構造にする。閉口時に唇の合わせ目が戻り、開口時には奥が塞がった口腔が見えるようにする。楕円の暗い円盤の貼付けで済ませない。
4. 鰓蓋は前方の付け根を保ち、実際の後縁を外側に小さく開く。薄い厚みと内部面を設け、背景や反対側が見える穴を残さない。頬全体の拡大を開閉の代わりにしない。
5. 固定面・可動面・内面のUVを分け、内部の暗色が体表へ補間されないようにする。元図の唇や鰓の線・影を二重に残さず、閉じた状態で深度競合を起こさない。

## GLBへ動作を保存する

ボーンまたはモーフをGLBへ内蔵し、標準glTFアニメーションで再生できるようにする。既存の鰭・遊泳チャンネルを保持する。HTMLのシェーダーやJavaScriptだけで動く版は、その実装先を[モデル機能一覧](model-contract.md)へ記録し、GLB単体でも動くと称さない。

口と鰓には少し位相差を付けた控えめな動きから調整する。周期・可動量・座標は魚種とモデルに合わせる。今回の作例の値を生理学的な標準値にしない。水槽側で同じ変形を二重に適用しない。

## 確認

- GLBを読み戻し、口と左右の鰓のチャンネル、再生結果、ループ端の連続性を確認する。
- 閉口・最大開口・最大開鰓・中間状態を、正面・左右・斜め・下面から確認する。口と鰓を独立に固定できるプレビューが診断に使える。
- 口角や鰓基部の隙間、二重の唇、内部色のにじみ、深度競合、伸びた模様を見る。口先の渦・楕円・輪は[UVの検査](quality.md#uvのつぶれと渦の確認)で診断し、同じ視点で再確認する。
- 基準形状・各可動形状・同時再生で、有限値・インデックス・縮退三角形と、閉じるべき部分を確認する。無関係な鰭・眼・尾柄の配列と模様を必要なく作り直さない。
