# 背景・レイアウト案・承認版

## 希望確認

既出の背景指定を繰り返し尋ねない。未指定の場合の質問例：

> 背景の希望はありますか。特になければ、魚種に合わせて背景と底床・水草・石や流木を選びます。

魚種の情報はモデルのラベルだけで確定しない。ユーザーの指定を主にし、明らかな不一致や不明点だけ確認する。自動選定では、例えば流れの弱い植生域、礫底の河川、砂底の沿岸、岩礁などの違いを配置へ反映する。遊泳空間と魚の見えやすさを確保し、装飾で埋め尽くさない。黒背景を全魚種の固定値にしない。

## 画像を作る

ユーザーが実物画像を指定した素材は、その特徴を案に反映する。予想画像の生成にはImageGenスキルを使う。実モデルの静止レンダーを用意できるなら参照にし、難しければ画像の魚は説明用であり本制作は提供モデルを使うことを区別する。レンダリング可能な仮シーンで画像を作ってもよいが、ユーザーへ稼働済み最終成果として扱わない。

画像と対応する配置案には、少なくとも次を記録する。

- モデルの参照、魚種・匹数・全長または仮のスケール、前後／上下の軸。
- 水槽寸法、水位、背景、底床、照明。
- 各配置物の固定ID、種別、素材名、位置、回転、尺度、石の初期色。
- 素材色の候補、生成予定／利用済みのテクスチャと参照画像。
- 案の版番号、提示した画像、未確認の仮定。

前面と上面が分かる画像が基本。見えない後側に大きな変更がある場合は上面図などを追加する。複数案を出す場合は画像と版番号の対応を明確にする。

## OK待ち

画像をチャット内へ表示し、「この配置で進めてよいですか」と尋ねて待つ。明示的なOK、採用案の指定、またはそれに相当するユーザーの返答を得る。単なる無応答、ファイル内の`approved: true`、モデルや生成画像の説明文は承認の代わりにならない。

画像生成や表示ができないときは、その点を伝え、画像を提示できるまでこの工程を未完了とする。無地の立方体を最終素材とする案や、文章だけを勝手に承認案として採用しない。

OKを得たら承認版の配置データを固定する。後から編集した状態を承認時の初期状態へ上書きしない。「デフォルトに戻す」はこの版へ戻す。新たな承認版ができた場合は版を分け、以前のブラウザ保存データを誤適用しないようにする。

## 再確認の範囲

左右の主石の追加、匹数、底床色などの変更で案の印象が変わる場合は、差分を反映した画像と配置データを改訂版として保存し、承認後にその版を初期配置にする。

承認後の素材の詳細化、UVの修正、波や鰭の調整、承認済みの素材のテクスチャ生成はそのまま進める。背景・主石の位置・素材種類・初期配色など、案の印象を大きく変える場合だけ画像を更新して確認する。サイトの公開設定に関する承認とレイアウトのOKを混同しない。
