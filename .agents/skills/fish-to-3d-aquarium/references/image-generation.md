# 画像生成（②三面図・④レイアウト案・⑤素材テクスチャ）

**ユーザーが明示的に依頼した部分修正は、修正とその確認・再修正を主担当だけで行う。確認のためにサブエージェントを作成・再開・呼び出さない。ユーザーがサブエージェントも合わせた確認を明示的に希望した場合だけ、指定された範囲で共同検品する。** 以下の「2体で確認」「全員OKまで反復」は共同検品の場合の規則であり、通常の部分修正には適用しない。初回の魚種調査・画像作成・3Dモデル検品は従来どおり共同検品する。

## 内蔵の画像生成がある AI（Codex）

各スキルの手順どおり、内蔵の image_gen で作る。

## 内蔵していない AI（Claude Code）

有料 API を無断で使わない。ユーザーに、普段使っている画像生成サービス（ChatGPT、Gemini など）の画面で作ってもらう。

1. AI がプロンプトを作る。**英語と日本語の両方を、そのまま貼れる形でチャットに直接示す**（生成サービスによって通りやすさが違う。ファイルに保存するだけにしない）。三面図は create-fish-3d-views の [prompt-template.md](../../create-fish-3d-views/references/prompt-template.md) を、調査結果で具体化する。
2. ユーザーに渡すもの：
   - そのまま貼れるプロンプト（英語の生成指示＋日本語の短い説明）
   - 添付してほしい画像（ユーザーの写真、選んだ画風に対応するネオンテトラの見本の[アニメ調](../../create-fish-3d-views/assets/neon-tetra-anime.webp)または[リアル調](../../create-fish-3d-views/assets/neon-tetra-realistic.webp)、ユーザー指定の画風見本など）と、その役割（写真は形・模様の資料、画風見本は線・塗り・質感の参照）
   - まず側面だけを1枚作る。ユーザーが側面の採用版を承認した後、必要な方向を同じ側面から別々に作る。
   - できた画像の保存先（例：`species/<id>/views/source/side.png`）か、チャットに添付してもらうこと
3. 受け取った魚の画像を、主担当と調査に参加した学術・公的資料担当/ホビー資料担当の2体で、[共同調査・検品](../../create-fish-3d-views/references/species-review.md) と create-fish-3d-views の確認基準に従って検品する。誰か1人でもNGなら修正事項を列挙し、修正用のプロンプトを渡してもう一度作ってもらう。同じ最新版に全員がOKを出すまで繰り返す。ユーザーの生成作業待ちは未合格として記録する。
4. 画像の実寸を記録し、生成サービス名とプロンプトを research.md か記録ファイルに残す。

⑤の素材テクスチャは [make-aquarium-textures](../../make-aquarium-textures/SKILL.md) に、プロンプトの型・加工・貼り方がある。ユーザーがイラストを提供している場合は、[keep-illustration-style](../../keep-illustration-style/SKILL.md) の画風句を全プロンプトに入れ、提供された画風を参照する。

## 画像を見られない AI

受け取った画像を自分で確認できない場合は、そのことを伝え、確認項目（research.md の特徴の一覧）をユーザーに示して、ユーザーの目で確かめてもらう。確認できていない画像を確認済みとして扱わない。魚の画像については、ユーザーの目視だけで全員の検品OKを代用せず、確認不能の担当は未判定として保留する。
