# 環境の確認と、導入を提案する条件

基本方針：**AI（Codex・Claude など）と、すでに入っているものだけで完結させる。** 新しいソフトのダウンロード・インストールは、代わりの方法が無いか劣る場合に限り、理由を添えて提案し、ユーザーの同意を得てから行う。

## 最初に確かめること

コマンドを実行できる AI は、次を確かめる（読み取りだけ。何も入れない）。OS に合わせて読み替える。

| 確かめること | 例 | 結果の使い道 |
|---|---|---|
| OS | Windows / macOS / Linux | コマンドの書き方 |
| Python | `python --version`（Windows は `py --version` も） | ③標準ルート、②の分割スクリプト |
| NumPy・Pillow | `python -c "import numpy, PIL; print(numpy.__version__, PIL.__version__)"` | ③標準ルート |
| Pillow だけ | `python -c "import PIL"` | ②の `package_views.py` |
| 画像生成 | AI 自身に内蔵の画像生成があるか | ②④⑤の画像 |
| ブラウザ | Chrome・Edge・Safari などが使えるか（ユーザーに聞いてよい） | プレビューと水槽の表示 |

SciPy は build-fish-3d-from-views で「あれば速くなる」だけなので、無くても入れない。Node.js はどの工程でも不要。

コマンドを実行できない AI（チャットだけの AI など）は、ユーザーに「Python が入っているか」を一度だけ聞く。分からなければブラウザ簡易版で進める。

## 判断

| 状況 | 進め方 |
|---|---|
| Python・NumPy・Pillow あり | ③は標準（build-fish-3d-from-views） |
| Python はあるが NumPy・Pillow が無い | ③はブラウザ簡易版。②は方向別に生成して分割を不要にする |
| Python が無い | 同上 |
| 画像生成が内蔵されている | ②④⑤の画像は内蔵で作る |
| 画像生成が内蔵されていない | ユーザーが画像生成サービスで作る（[画像生成](image-generation.md)） |

## 導入を提案してよいとき

- ブラウザ簡易版の精度では、ユーザーの求める再現度に届かないとき（例：口・唇・鰭の付け根の立体、背腹の模様の連続など、標準ルートでしか作れない部分が重要なとき）。
- その場合も、次を短く伝えてから同意を求める：何を入れるか（Python 本体、NumPy、Pillow）、なぜ必要か、入れないとどうなるか、どこから入れるか（python.org など公式の配布元）。
- 同意が無ければブラウザ簡易版のまま進める。断られたことを理由に作業を止めない。

## 提案しないもの

- 画像生成・3D生成の有料 API や、外部サービスへの登録（ユーザーが自分から望んだ場合を除く）。
- 確認画像を撮るための自動ブラウザ操作ツールなど、作業の便利さのためだけのもの。画像はユーザーにプレビューを開いてもらって確認してもよい。
