# 外部3Dツールで高品質モデルを作る（ユーザーが望んだときだけ）

**ユーザーが明示的に依頼した部分修正は、修正とその確認・再修正を主担当だけで行う。確認のためにサブエージェントを作成・再開・呼び出さない。ユーザーがサブエージェントも合わせた確認を明示的に希望した場合だけ、指定された範囲で共同検品する。** 以下の「2体で確認」「全員OKまで反復」は共同検品の場合の規則であり、通常の部分修正には適用しない。初回の魚種調査・画像作成・3Dモデル検品は、開始時にユーザーが選んだ検品体制（共同検品／主担当のみ。希望がなければ主担当のみ）で行う。

標準は外部ツールを使わない（build-fish-3d-from-views）。
ユーザーが「もっと写実的なモデルにしたい」などとはっきり望んだときだけ、この道を案内する。AI から提案して誘導しない。

## 流れ

1. ②で承認された三面図（側面・背面・腹面の個別PNG）と、ユーザーの写真を用意する。
2. ユーザー自身のアカウントで、画像から3Dモデルを作るサービスを使ってもらう。例：Tripo（複数視点の画像入力に対応）、Meshy、Rodin（Hyper3D）、Hunyuan3D。料金・利用規約・生成物の扱いはサービスごとに違うので、ユーザーに確かめてもらう。AI がユーザーの代わりに登録・ログイン・支払いをしない。
3. できた GLB を `species/<id>/model/external/` に保存してもらう。
4. build-aquarium-from-fish-model の `scripts/inspect_glb.py` で構造（軸・単位・スケール・材質・画像・骨）を確かめる。
5. ③と同じように、選ばれた検品体制（共同検品なら主担当と①から参加する学術・公的資料担当/ホビー資料担当の2体、主担当のみなら主担当）が、実モデルから描画した全方向と重要部位を[共同調査・検品](../../create-fish-3d-views/references/species-review.md)の基準で確認する。誰か1人でもNGなら修正事項を列挙してモデルを直し、全員（主担当のみなら主担当）が同じ最新版にOKを出すまで再検品する。その後に画像を提示し、ユーザーのOKをもらう。生成モデルは部位の有無・位置や模様がくずれやすいので、見た目がそれらしくても特徴の確認を省かない。
6. OK が出たら `project.json` の `model_route` を `external` にして記録し、⑤へ渡す。
7. ⑤で鰭を動かすときは [rig-tripo-fish-fins](../../rig-tripo-fish-fins/SKILL.md) に従う（鰭の判定、胸鰭・腹鰭のボーン、体と癒着した鰭の切り離し、体に描き込まれた胸鰭の消去）。

## 注意

- 外部モデルは頂点数・画像サイズが大きいことがある。スマホで見る水槽では build-aquarium-from-fish-model の mobile-performance.md に従って軽くする。
- 外部モデルの誤りを直す場合、承認済みの部分を作り直さない。直せない誤りは未合格として記録し、そのことを伝えて標準ルートでの作り直しを提案する。ルートを変えても全員OKまでの検品を省かない。
