# 確認と局所修正

**ユーザーが明示的に依頼した部分修正は、修正とその確認・再修正を主担当だけで行う。確認のためにサブエージェントを作成・再開・呼び出さない。ユーザーがサブエージェントも合わせた確認を明示的に希望した場合だけ、指定された範囲で共同検品する。** 以下の「共同検品」「全員OKまで反復」は共同検品の場合の規則であり、通常の部分修正には適用しない。初回の魚種調査・画像作成・3Dモデル検品は従来どおり共同検品する。

## 主担当と調査担当で検品する

[共同調査・検品](../../create-fish-3d-views/references/species-review.md) に従い、調査に参加した担当にも、実モデルの確認画像と補完判断の根拠を渡す。主担当を含む誰かがNGなら部位・問題・根拠・修正を列挙して直し、同じ最新版に全員がOKを出すまで再検品する。数値検証の成功だけで全員OKにせず、各担当が実際に見た版と判定をreviews.mdに記録する。写真で見えなかった部位は鰭に限らず全て確認する。

## 全体と拡大を両方見る

実メッシュとUVの描画で、左右、正面、背面、上面、下面を確認する。確認画像だけ別の絵にしてはいけない。図の対応方向と比較し、必要なパーツを近接描画する。

| 症状 | 確認と修正 |
|---|---|
| 鰭や眼が二重 | 胴体に残った絵・影と独立形状を確認。胴体用画像だけを補修する |
| 腹鰭の数・構造が資料と違う、または腹に絵だけ残る | 左右独立の対鰭か、ハゼ類などの癒合した吸盤かを資料で判定する。必要な立体を作り、腹面に残った重複の絵を除く。下・前から確認 |
| 口がO形、口が小さくなる | 元の口を拡大して再確認。閉口なら上下唇と細い合わせ目。単に楕円のサイズを変えない |
| 口から腹が放射状に割れる | キャップのUV、投影の切り替え、透明背景の混入を確認。鼻先・腹用の連続色場へ |
| 尾柄に輪・穴・不連続な模様 | 尾柄の周囲のUVと形状の接続を確認。黄色等は全周で一続きにする |
| 突起が消えた | 図の付属器官一覧とメッシュ名を照合。塗り直した体色と立体の色を別に割り当てる |
| 黄色い細枠や白い縁 | 元の境界の混色、背景、ミップマップを確認。明色の閾値だけで削除しない |
| 鰭・唇の付け根が浮く | 上下・斜めから根元を描画。裏側の形状を胴体へ延長して接続する |
| 鰭膜の一部が欠ける | 輪郭の省略、過剰な埋め込み、UV島の上書き、背景色を区別し、元図の膜の面積と照合する |
| 尾鰭を後付けしたように見える | 前面壁やキャップの重なり、断面・法線・色の段差を確認。[接合部の手順](fin-junctions.md) に従う |
| 条だけが離れて見える | 添付位置と該当部位を対応させ、形態上の独立と接続不良を区別する。指定でつなぐ場合は膜と条を一続きにする |

## 全魚種で確認する鰭・体表・開口

対象種にある部位について、承認図と資料を実モデルに照合する。

- **参照個体の鰭の状態**。裂け・欠け・畳み込みを、種本来の切れ込み・遊離条・鰭膜の形と区別する。通常形態を再現する場合は資料に沿って損傷部を補う。対象個体そのものの再現が指定された場合は、その個体の状態を反映する。
- **鰭の起点・輪郭・接続**。起点、間隔、重なり、連続膜を対象種の資料に合わせる。胸鰭がある種では側面図と3Dで輪郭と付け根を照合し、可動モデルでは左右の開閉の両端でも確認する。
- **透過と胴体模様**。鰭膜・鰭条・色素・基部の透け方を対象種の資料で確認し、膜の透過と鰭条の濃さを別に調整する。胸鰭を分離したモデルでは、鰭を隠して鰓蓋から体側への模様の連続性を見て、開閉時の切り抜き跡とめり込みを確認する。
- **背面・鰭の縁**。真上から背面の模様と背鰭・尾鰭基部の塗り残しを、後方と斜めから鰭の縁の欠け・切り残し・テクスチャの継ぎ目を確認する。
- **口線と開口位置**。承認図の口線・口角を3Dの開口位置と照合する。可動モデルでは閉口・開口を側面と斜めから確認する。

## UVのつぶれと渦の確認

1. GLBを書き出したら、鼻先、尾柄の端、ほかに露出するふた面を、面に正対した角度と斜めから拡大する。渦、放射状の引き伸ばし、ぼけた楕円、細い輪を探す。口が動くモデルは閉じた状態・開く途中・開いた状態で見る。通常の鑑賞倍率でも確認する。
2. [ローカル実装部品](toolkit.md)の `check-uv` で、3Dでは面積があるのにUV上で線や点に近づく面を絞る。照明ありと `render --unlit` の拡大画像を同じ視点で比較する。色だけで見える場合はUVやテクスチャ、照明で現れる場合は断面の接線・法線も調べる。意図した単色パーツは別扱いにし、検出がゼロでも外観は確認する。
3. 胴体の長軸位置と周方向角度でUVを作る場合、端のふた面は長軸位置が一定なので、外周と中心がUV上の同じ列に潰れ得る。該当面には面積を持つUVを割り当て、近くの皮膚の色と模様を形状に沿ってベイクする。別のUV領域に切り替えた境目が輪になる場合は、先端と隣接面を同じ領域に広げ、共有する位置でUVをそろえる。平らな面や硬い法線の境目も原因に含まれる場合は、元資料に沿って先端を丸め、周囲の法線とつなぐ。
4. 修正後のGLBを読み戻し、同じ視点とポーズで数値検査と拡大描画をやり直す。唇の合わせ目、尾柄の本来の模様、開閉時の変形も照合する。修正した部位と確認に使った版を検品記録に残す。

## 素材・尾柄・投影の継ぎ目を切り分ける

症状だけで原因を断定せず、元画像→清掃した胴体画像→輪郭と接合マスク→UV→材質・フィルタリング→実描画を比較する。形状を直すべき隙間を画像の塗り足しだけで塞いだり、模様の乱れをぼかして隠したりしない。

| 症状 | 確認する候補 |
|---|---|
| 灰色の単色部 | 胴体輪郭のはみ出し、背景混入、未充填の画像領域 |
| 鰭との隙間 | マスクの削り過ぎ、接合帯の不足、可動時に根元が離れる変形 |
| ギザつき・斑紋の引き伸ばし | 原画像の解像度、UVの面積と歪み、投影の切替、輪郭のサンプリング |
| 茶色いぼかし・白い霧 | 鰭色や背景の混入、近傍色の過剰な延長、UV島の余白とフィルタリング |
| 背側と体側の質感差 | 各参照画像の線幅・斑紋密度・鮮明さと、投影を混ぜる範囲 |
| 背鰭の輪郭線が体表に残る | 鰭なし画像の清掃漏れ、UVが別部位を参照していないか |

尾柄の上下は側面だけでなく、真上・真下・斜め後方から見る。元図にある切れ込みと接合部を区別し、必要な鰭膜の面積を保つ。通常版と軽量版で見え方が違う場合は、実際に読み込んだ画像・フィルタ設定も比べる。渦・楕円・輪は上記の「UVのつぶれと渦の確認」で診断する。

## 鰭の輪郭を局所修正するとき

1. 赤線などで輪郭の指定がある場合は、元図に重ねて基部の始点・終点、先端、前縁・後縁を別々に記録する。基部を先に合わせ、隣の鰭との間隔を見てから高さや幅を調整する。ハチマキダテハゼでは、第一背鰭の先端に加え、前方の起点を合わせることで輪郭が指示と整合した。
2. 鰭膜を広げた箇所では、旧輪郭や途中で切れた鰭条を除き、基部から新しい外縁まで鰭条をつなぐ。拡大して、鰭膜の中に旧輪郭や交差する描き直し線が残っていないか確認する。
3. 欠けの補修では、輪郭とUV・アルファのどこに欠損があるかを切り分ける。輪郭を広げたら、追加した膜へ近くの膜色と鰭条を延ばし、旧縁の線や背景色を採らない。ヤマブキハゼの尻鰭前縁のような補修は、付け根から外縁の連続を左右側面と斜めから再描画して確認する。

## 可動版の確認

[標準の鰭アニメーションの合格条件](fin-animation.md#合格条件)を適用する。基部からの滑らかな開閉と先端の遅れ、部位・個体別の位相、速度・旋回・停止への連続性を確認する。接合帯の追従、変形時の面の潰れ・反転・陰影、GLB基本ループの読み戻し、水槽側との二重適用も確認し、通常／軽量の実装状態を記録する。

[モデル機能一覧](model-contract.md)の対象版をGLBから読み戻す。口・鰓・各鰭を独立に確認した後、最小・最大・中間と組合せを見る。膨張中の呼吸・鰭、採餌中の口・鰓・頭部など、実際に同時再生する状態を含める。ループ端の連続性、眼の埋没・突出、可動部の隙間を確認する。静止時の閉鎖検査だけで可動形状や模様の品質を合格にしない。

## 数値で見るもの

- GLBのヘッダ長とチャンク、画像内蔵、バッファ範囲、アクセサ長、インデックス範囲。
- 座標・UV・法線の有限値、法線の長さ、縮退三角形。意図せぬ法線反転も実描画で確認する。
- 両面表示だけで穴や裏向きの閉じた胴体をごまかさない。厚みのある独立形状は、位置を同一視した辺で各辺が2面に接するかも調べる。
- 全長・中心・Y上・頭尾方向と、ルート変換がすべてのパーツに一貫すること。
- パディングを含めたUV島の矩形が範囲内で重複せず、別領域への配置でも棚の状態が壊れないこと。閉鎖検査とは別に調べる。
- 連続面として接続した尾柄・尾鰭は組立全体の閉鎖と共通リングの位置・法線を確認する。先端・膜の面積の検査は画像比較も行い、パーツ数や三角形数だけで合格にしない。

`fish_mesh.py validate model.glb` はこのライブラリの単一アトラス出力向けの構造検証。他の拡張・圧縮形式を読める汎用glTF認証器ではない。検証できた項目だけを報告する。

## 修正時

承認済み版を残し、修正対象を特定してから触る。テクスチャの塗り残し修正なら、位置・法線・UV・インデックスを維持し、対象島の必要な領域だけを直す。作り直した場合は配列またはバッファを比較して、口や鰭が元に戻っていないことを確認する。

複数回の小変更のたびに全方向の高解像度レンダーを繰り返さない。最初に全体を確認し、局所修正では該当部位の近接画像と変更範囲を全員で確認する。旧版の全体画像を併用する場合は、何が変わったか分かるよう版と対象を明記する。新版の全員の明示的な判定は省かない。新たな形状変更・不明点が出たときに確認範囲を広げる。

新版GLB、同じ形状・テクスチャを持つHTML、局所の確認画像を更新する。ファイル名の版、プレビューの見出し、ダウンロード先が一致していることを確認し、ユーザーが見ている旧版と混同しない。
